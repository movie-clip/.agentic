# Changelog — `.agentic`

Provenance for the agent network: what changed in each version, and the
evidence that earned it. The current design lives in
[`ARCHITECTURE.md`](./ARCHITECTURE.md); this file is why it is shaped that way.

Its reader is a human deciding whether to trust a rule — `protocol/authoring.md`
§ "Writing for the reader you actually have" keeps this history out of the
agent-facing files, which are read once per dispatch, many dispatches per run.

**Three conventions.**

- **Newest first.** The version in
  `plugins/agentic-core/.claude-plugin/plugin.json` is the authority on what is
  installed; the top entry here should match it.
- **Entries are not retro-edited.** Each describes the state at its own release
  and is left standing when a later version supersedes it — so an entry may name
  a script, rule or count that no longer exists. `run_cost.py` in v0.4.8 is the
  worked example: v0.5.7 deleted it. Read down from the top for the current
  state, not up from the bottom.
- **Runs are cited by id, never by path.** Closed runs are pruned once what they
  taught is in the protocol (`projects/<name>/runs/README.md`); their artifacts
  stay in git history. A run id here is durable, a path would not be.

v0.4.5 has no entry of its own — what it settled is recorded in v0.4.4's second
bullet.

---

- **v0.7.5 — the authoring gate's trigger now names the layer it already judges.** `protocol-linter`'s `description:` is the routing surface — it is what the orchestrator and Claude Code's own agent selector read to decide *whether* the gate is dispatched — and it enumerated four subjects: an agent definition, a capability pack or project profile, a section of `PROTOCOL.md`, a section of `protocol/`. `skills/` was not among them. It now is.
  - **the rules were never the narrow part; the trigger was.** `authoring.md` § "The four-layer split" has carried the Skill layer as a peer of the other three, with *any rule the protocol states* in its **Must not contain** column, since before the drift it would have caught; § "A skill is not a fifth place to put a rule" states the case in its own paragraph and names `orchestrate-feature`; and the linter's own rule table has cited `SKILL.md` under rules 1 and 2 since v0.7.3. So an order that edits only a `SKILL.md` would have been judged correctly had it ever been routed — it just did not match the sentence that does the routing. A gate whose rules reach further than its trigger fails silently, because nothing reports a dispatch that never happened.
  - **the four-gate table was narrow in the same way**, in `protocol/gates.md` and its mirror in `ARCHITECTURE.md`: *an agent, pack or protocol section that breaks `authoring.md`* now reads *an agent, skill, pack or protocol section*. Three enumerations of one subject, and the two that were written as prose lists both dropped the newest layer while the table that defines the layers kept it — which is the argument for citing the split rather than restating it.
  - **nothing about what the linter checks changed.** This widens what routes to it. The lane has still never been dispatched: 267 recorded dispatches, zero `protocol-lint`, across the 22 days since it was added — including the v0.7.3 and v0.7.4 edits to the network's own files, which are exactly its trigger. `authoring.md` already records that it has never run and what to judge its first verdicts on.
- **v0.7.4 — the mathematics lane is named for the job it does.** `quant-analyst` is now `quantitative-researcher`. The old name was the weaker of the two titles the work maps to: at a fund, *quantitative analyst* is the sell-side pricing-and-risk role, while the person who defines a metric, derives its formula, grounds it in the literature and rules on what is honestly computable is a **quantitative researcher**. The agent's own opening line already called it "the quantitative analyst"; the file now says what it is.
  - **the rename is total, because a partial one fails a check.** `check_models` resolves the ledger's `agent` column to `agents/<name>.md` and reports a row naming an agent with no definition — so a rename that missed one reference would surface as a closed ledger failing its own sweep. 26 references across 11 files, the definition file itself via `git mv`, and the prose that called the role "the quant analyst" in `producer.md`, `story-author.md` and the README tree. Both surviving ledgers cite the **lane** (`quant-audit`), never the agent, so neither broke; `176/176` and `20/20` still pass and `claude plugin validate` is clean.
  - **the lanes and the modes were deliberately not renamed.** `quant`, `quant-audit`, `RESEARCH` and `AUDIT` are protocol identifiers, not job titles: `check_report.py` holds the lane list, the gate set, and the rule that a `quant` row in `AUDIT` mode *is* the `quant-audit` lane; 176 assertions rest on those spellings, and closed ledgers are written in them. Renaming a lane would edit code and rewrite history to relabel an internal address. `AUDIT` → `VALIDATION` was considered on the same grounds and declined for the same reason — *audit* is not wrong, only less specific than the model-risk term.
  - **one researcher holds two functions, and that is the small-fund arrangement, not an oversight.** Banking supervision separates model development from model validation precisely so the second is an independent challenge to the first (Fed SR 11-7); a firm of this size does not have two people. What preserves the independence here is structural rather than organisational: each dispatch is a fresh context, and `phases.md` already refuses to accept the weaker version of it — *an audit that recomputed from the same methodology doc the implementation was built from is a consistency check, not an independent one*. The evidence says the two-mode dispatch works: of 30 recorded dispatches, 16 named `AUDIT` and 14 named `RESEARCH`, **none was ambiguous**, and four sessions ran both.
  - **splitting it into two agents was evaluated after the rename and rejected on the network's own rules.** 99 of the file's 239 lines are mode-specific; 108 are shared — the binding block, the `## Standing rules`, the orchestrator brief and the output format. A split duplicates that 45%, and the standing rules (*never invent a formula*, *never approve a number you could not reproduce*, *prefer withholding to publishing*) have nowhere legal to go: `protocol/` may not hold "anything about a specific role's craft" and a capability pack may not hold "role definitions", per `authoring.md` § "The four-layer split". So the split forces either a second copy of the doctrine or a layer violation. **The trigger that would change this answer is a single line of frontmatter**: the day RESEARCH and AUDIT want different `model:` or different `tools:`, one file cannot declare two, and the split becomes mechanical rather than aesthetic.
  - **`ARCHITECTURE.md`'s version heading had gone stale at 0.7.2** while `plugin.json` read 0.7.3 — missed when v0.7.3 was written, in the one file whose own third line says *this heading has been wrong before*.
- **v0.7.3 — the entry point stopped asking the model to load itself.** `commands/feature.md` opened by instructing the session to invoke `orchestrate-feature` via the Skill tool "before reading anything else", then restated five non-negotiables inline as a safety net for the case where it did not. The instruction was the only non-deterministic step in a chain that is otherwise deterministic, and the safety net was a second copy of rules the skill already carried.
  - **the hop was never needed.** Claude Code loads a command file and a `SKILL.md` through one loader and one frontmatter schema; typing `/<name>` injects the file body verbatim as a synthetic user turn before the model acts. Verified against the installed 2.1.269 binary and against the transcripts: `/agentic-core:feature` delivered 2,698 characters with no model decision involved, and `/doctor` — a skill, not a command — delivered 44,667 the same way. A command body whose first line says *now go load the real file* spends a round-trip asking the model to fetch what the harness had already handed over for free.
  - **what the 34 recorded runs actually show.** The orchestrator skill loaded in 26 of them. Seven produced no assistant turn at all — five were the command re-typed within seconds of a run that then succeeded, two were aborted before the model answered — so they are not runs. The single run that did lane work without loading the skill had it in context already, from a run 41 seconds earlier. There is no recorded case of the safety net catching a drifted session. What the split did cost is visible twice: the session invoked `agentic-core:feature` — the command itself — before reaching `agentic-core:orchestrate-feature`, because *invoke the skill* is ambiguous when the command and the skill sit in the same list under near-identical names. Removing the command removes the ambiguity rather than arguing with it.
  - **the safety net was a sixth home for five rules.** Each already lived in the skill, and in every case more precisely: the banner and its version provenance (§ `intake`, which also names the stale-cache case the command did not), the no-lane-work fence (which names the three files the orchestrator may write), *before stating a conclusion, ask whose it is*, the `dispatched: <n>` disclosure, and urgency. `authoring.md` § "A skill is not a fifth place to put a rule" is the rule this broke, and the two copies had already drifted — the command made `dispatched: 0` unconditional where the skill exempts a pure `ground-truth` run.
  - **`commands/` is gone; the skill is the entry point.** `/agentic-core:orchestrate-feature <request>` injects the loop itself, with `$ARGUMENTS` placing the request at a fixed position rather than relying on the runtime's append fallback, and `argument-hint` carrying the placeholder the command used to own. Description-triggered entry is unchanged. The invocation is one word longer and deterministic by construction.
  - **the same hop, one level down.** The skill opened with *Load `agentic-protocol` before anything else* and then, in the same sentence, named both files that skill would have sent it to. `orchestrate-feature` was its only reference in the network — every specialist binds by path under `PROTOCOL.md` § 1 instead — so the indirection bought nothing the sentence did not already say. The orchestrator now binds by path like every other lane. The stub is left in place: it is still reachable by description for a lane that goes looking for the contract, and it now has no explicit consumer, which is a question for the next authoring pass.
  - **a gap this exposed and did not close:** `protocol-linter`'s authoring scope names `agents/`, `projects/`, `PROTOCOL.md` and `protocol/` — not `skills/`, and not the `commands/` that just carried the drift. The one network file holding a duplicated rule set sat outside the gate that exists to catch duplicated rule sets.
- **v0.7.2 — the planning chain: not a merge, a narrower trigger and one missing path.** The proposal was to fold `product` and `story` into one lane — two dispatches, two human stops and two full pack reads for what looks like one act of specification. The two long runs refuse it, and name a different defect in the same place.
  - **why they stay two lanes.** In both recorded runs, evidence-gathering ran *between* them: `2026-09-09` went brief → quant research → recon → story, `2026-09-11` went brief → quant research → story. The story lane's most valuable output on the long run — catching that the work order's 20-observation premise was false, three contract notes, four open decisions — came from artifacts that did not exist when the producer ran. A merged lane either runs before that evidence and cannot use it, or runs after it and the framing stop disappears. The two stops are also different questions: *does this belong in the plan* is the cheapest place to kill work, *are these the right acceptance criteria* is the most expensive to get wrong, and collapsing them asks the human to approve both in one artifact. And the tool boundary is real — `producer` is read-only; `story-author` writes into the repo. The standard test for splitting an agent is a distinct decision, a distinct tool set or a distinct context; this pair is three for three.
  - **what was actually duplicated: `product` and `recon`.** `2026-09-09` dispatched the producer first, and its brief established what the code does by opening source files — its own `risks` block conceded *"'Already covered' rests on claims I opened myself"*. The scout then ran two dispatches later over the same territory and **contradicted it**: the Dashboard volatility path has no 20-observation floor, which the brief had asserted it did. Two dispatches, one of them wrong, and the correction surfaced only because a third lane read both. `project.md` now declares `ground-truth` before `framing` as a non-negotiable ordering, and the producer's pack requires every claim about the code to be cited from a `recon` artifact in its `inputs` or marked unverified.
  - **the human's ruling is a path now.** The relay rule made every judgment in a run a file, with one exception it never named: the human's. `2026-09-11`'s story lane wrote it down itself — *"I did not see a separate signed ruling document, only the work order's own restatement of the producer's brief's two open items as resolved."* It was right, could not check, and drafted against the paraphrase. Every human stop now ends by writing the ruling to `<run_dir>/decisions.md` in the human's own words, with the artifact and section that raised it, and downstream orders name `decisions.md § D-<n>` in `inputs`. `check_decisions` fails a close-out whose profile marks a phase as a human stop, whose ledger says the run passed it, and whose run dir has no decisions file. It is also the only part of a run that did not otherwise survive a compaction.
  - **the story row's trigger got narrower, which is the merge's real content.** It fires when framing produced uncovered scope **and** the slice needs ticketing — more than one build lane, a contract crossing, or mathematics. Otherwise the delivery brief the human already approved is the specification, the row reads `not triggered (single-lane slice; the brief in <nn> is the specification)`, and `review` does not fire either because its own clause asks for a story to accept. `2026-09-11` is the case: a 28-line story with two tickets and no contract notes, restating a brief the human had approved, followed by an acceptance gate judging criteria written from that restatement. That is the dispatch the merge proposal was reacting to, and removing it costs no judgment — where judgment is actually needed, the trigger still fires.
  - **runs are pruned now.** `2026-09-09` and `2026-09-11` are gone from the tree; what they taught is in this entry and in the protocol, and their artifacts are in git history. The retention rule is in `projects/<name>/runs/README.md`: a run earns its disk while it is open, while its work is uncommitted, or while it is evidence for a change not yet made. **Cite a pruned run by its id, never by a path** — which also repaired two references that had been dangling since August, one in `README.md` telling a reader to open a deleted directory and one in `capabilities/quant.md` resting a methodological claim on a deleted artifact.
- **v0.7.1 — the first run under the phase model, and the five things it got away with.** `2026-09-12-combine-sector-benchmark-card` closed clean by every reading available at the time: four dispatches against a budget of five, `integration PASS`, `check_report.py --require-heads` exit 0. It also closed with four `## Phases` rows still reading `pending` beside four completed dispatches, a `gates:` line asserting a file was empty that was eleven lines long, a work order that told a lane a spec file "still asserts the old DOM shape" when no such file had ever been in git history, and a gate that ran three sub-commands instead of the project's acceptance command — leaving work the human's commit hook would have refused. Every one of those was a rule the protocol already stated in prose, and prose is what the route enum was replaced for.
  - **the termination condition is checked.** `check_phases` fails a CLOSED ledger holding a `pending` row, and fails `not triggered` written without the clause that was false. § 3 said a run may close when every row is accounted for; the run that said it hardest is the run that did not, and the close-out checklist asking nicely was the whole enforcement.
  - **`spent` is checked against the dispatches on disk.** `check_budget` fails when the count disagrees with the Artifacts rows — which makes the failure § 1 spends three paragraphs on, a dispatch that happened and was never recorded, visible for the first time. A dispatch that returned nothing now owes a row too (`LOST`), re-dispatched as the next slot, so the budget is the true account of what the run spent rather than of what it has artifacts for.
  - **orders carry sourced claims.** `orchestrator.md` § 6: every factual claim in a work order is something you read this turn or something a path in `inputs` says. Needing one and having neither *is* the `ground-truth` trigger. The run skipped that phase on an intake grep and spent three lanes' attention on one unverified sentence — a frontend lane repeating it, a test lane disproving it from git history, an `Open` row carrying it to close-out. Nothing shipped wrong, which is exactly why it would have happened again.
  - **the gate runs the project's acceptance command.** `project.md` § What the gates run, and `capabilities/architecture.md` § 6: `integration` runs `run_all_tests.py`, always, whatever the lanes touched. It is the only command that writes `.claude/.last-test-pass`, so a gate that runs less returns `PASS` on work the commit hook will refuse — which is what happened, and what nobody noticed until the suite was run by hand afterwards.
  - **`- none — commentary` blocks instead of advising.** One ambiguous bullet in the docs lane's report inflated its head count to 1, which opened a `pack-corrections.md` with nothing in it, which put a false claim about that file into the ledger's `gates:` line. Three records wrong from four surplus words. Blocking is also what reaches `scout`, `story-author` and `docs-engineer`, since they have no `Bash` and `report_artifact_gate.py` drops advisory notes — and the lane that broke this rule was one of those three.
  - **`pack-corrections.md` exists only when a correction applies.** A file opened to record that there was nothing to correct makes the authoring gate accountable for nothing; the lane's own `pack_corrections: - none` is already that record.
  - **the budget lost its slack.** `4 + 1 slack, spent 4` cannot say whether the model was calibrated or the padding absorbed the miss. One dispatch over an honest estimate costs a `## Replans` row, and that row is the measurement the padding was buying off.
  - **a row can leave `Open` by being dismissed.** `CARRIED` means the human is owed something; the run had no way to close a note about its own work order, so it carried one to close-out and reported it as an open item.
  - **both v0.7.0 debts closed.** The gate set is read from the profile's `## Phases` verify rows (`profile_gates`), with the hard-coded triple as the fallback for a ledger whose profile cannot be resolved; and `runs/` moved to `projects/<project>/runs/`, which is also what lets a run dir find its own profile from its path. A second project now needs no edit under `plugins/` and no edit to the validator.
  - **deliberately left:** `04-docs.md` still fails the new sweep. Reports are immutable once written — the lane said so itself, declining to edit its own — and a closed run that fails the check that would have caught it is a better fixture than a tidied one. Validator suite: 112 → 149 cases.
- **v0.7.0 — the route enum the runs had already stopped using.** The six-value route table was the run's control structure: it fixed the dispatch count and the step order before the request had been read against anything. `2026-09-11-risk-summary-audit-foldable` recorded `route: audit + producer-referral` — not a value the enum defines — then ran `05-frontend` before `06-technical-plan` and `09-backend` after `08-integration`, across 16 dispatches with no recorded moment where anyone decided 16 was acceptable. The run was fine. The script was fiction, and the ledger had no field in which to say so.
  - **phases replace the route.** `orchestrator.md` § 2: eight phases — `intake`, `ground-truth`, `framing`, `specification`, `design`, `build`, `verify`, `close` — each with a trigger evaluated against *this* request, in an order that is a dependency rather than a schedule. A phase that does not fire is recorded as `not triggered (<the clause that was false>)`, which is the thing a route name could not give: `route: express` says a short run happened; the clause says which question went unasked and on what grounds, so a later reader can tell a decision from an omission.
  - **the express lane is gone and nothing replaced it.** A run where `framing`, `specification` and `design` all fail their triggers *is* the short run. The self-voiding rule went with it — a false clause is re-read every turn, so a contract note that falsifies one is a re-plan with a row, not a route quietly discovering it was the wrong one.
  - **the skill is a loop over the ledger, not a numbered script.** `orchestrator.md` § 3: read `run.md`, take the earliest unsatisfied phase whose trigger is true, stop at a human stop, write before you spend, dispatch one order, absorb the head, re-plan if reality disagrees. The re-read each turn is what makes a compacted or restarted session identical to a continuing one. The ledger was already the state; Steps 0–10 were a second copy of it that existed only inside the session.
  - **a derived budget replaces the route's dispatch count.** The table fixed 1–12 dispatches by name, chosen before the run knew anything. The budget falls out of which triggers actually fired, `spent` increments per dispatch, and at `spent == budget` nothing dispatches until a `## Replans` row says what the estimate missed; twice the budget is a hard stop. `spent` against `budget` is the only number in the ledger that measures the estimate rather than the work.
  - **re-planning is versioned.** Four named triggers — a `BLOCKED` that is not a missing input, a result that *contradicts* the plan, a `not triggered` clause turning true, `spent` reaching `budget` — then `plan: v<n>` and a `## Replans` row. Step 6.8 said "re-plan when reality disagrees" with no threshold and nowhere to record that it had happened.
  - **serial stayed serial, deliberately.** The published gains from 3–5 parallel subagents are real, and they are not available to a network whose relay needs the upstream head on disk before the downstream order is written. The exception is three clauses wide — no shared files, no shared artifacts, contract already settled — and covers the read-only lanes at the start of a run. Cheaper to say no than to find a contract mismatch at the integration gate.
  - **the sequencing layer stopped knowing what a quant is.** `orchestrate-feature` hard-coded quant research before story authoring, the quant audit before integration, "no formula, weighting, return basis or trust classification" inside the express gate, and a roadmap/epic/story vocabulary throughout — so a second project needed a forked skill, which is the one thing the three-layer split exists to prevent. All of it is now `projects/portfolio/project.md` § Phases: a lane-per-phase table with a `fires when` clause, the three ordering arguments beside it. The plugin names no lane the profile has not declared. 536 → 421 lines.
  - **still project-shaped, and deliberately left:** `check_report.py` hard-codes `LEDGER_GATES` as this project's three `verify` lanes instead of reading the profile, and `runs/` still sits at `<agenticRoot>/runs/` rather than under the project it belongs to. Both block a second binding; neither blocks this one. **Both closed in v0.7.1.**

- **v0.6.0 — the one order that always writes network files, and the gate defined never to see it.** `protocol-lint` sits outside `LEDGER_GATES` on purpose: it judges the network's own files, and a `skipped (not an authoring order)` line on every delivery run is a line nobody reads. But the close-out `pack-corrections.md` dispatch *is* an authoring order — `packs.md` § 3 makes it the only order in which a lane writes inside `<agenticRoot>` outside the run dir — and it arrives inside a delivery run, which is exactly what the exclusion excused. `2026-09-11-risk-summary-audit-foldable` is what that costs: the docs lane rewrote 51 lines of `capabilities/product.md`, said in `risks` that the edit went past what `packs.md` § Applying corrections permits, and nothing gated it. The trigger is now the file, not the route — a non-empty `pack-corrections.md` obliges the `gates:` line to account for `protocol-lint`, with a verdict or with `skipped` and a reason (`check_authoring_gate`, 5 new cases, 112 total). It fails that run by design; the ledger is left unedited as the evidence, per the v0.5.6 precedent.
  - **what the first post-v0.5.9 run showed.** 16 dispatches, every head saved and every head agreeing with its artifact, `gates:` naming all three delivery gates, and an `Open` table that closes clean under `check_open_table` — 4 deliberate `CARRIED` rows against a populated `## Closed` table, where the previous run left 13 of 18 resolved rows sitting in `Open`. Bullet-discipline warnings fell from 8.1 per artifact to 5.3, and mean artifact size from 14.7 KB to 8.5 KB across 33% more dispatches. One run is not a trend, and the two runs differ in shape; what is not ambiguous is that the ledger contradiction the v0.5.9 pass removed no longer reproduces.
  - **`orchestrator.md` stopped carrying its own changelog.** The extension had accumulated a habit: each rule followed by the run that produced it, named and dated. That is provenance, and `authoring.md` already says where provenance goes — here, whose reader is a human deciding whether to trust the design, not a model paying for it once per dispatch. Every incident it cited was already in this file, so the citations were a second copy as well as a cost. The rules keep their *why* in the present tense, the gate list became a table of when each gate is accountable, and the new `protocol-lint` trigger is stated inside that rule instead of appended to it as a fifth paragraph arguing with the fourth. Roughly 200 words of history out, the same volume of rule in.
  - **the planning-doc model, replaced rather than mourned.** Four of this run's `pack_corrections` were the same fact: `capabilities/product.md`, `capabilities/docs.md` and `project.md` still taught a roadmap/PRD/story-index corpus deleted at `ce9c97d`, and the packs had been rewritten to teach its *absence* — three files explaining that there is no plan. The bound repo now derives `docs/product/ROADMAP.md` from story frontmatter (`scripts/build_roadmap.py`, gated by `run_all_tests.py`), epics are optional files rather than required parents, and the packs point at `docs/product/planning.md` instead of describing a hole. Same move as `--emit-head`: the index is derived from the artifact, so the two cannot disagree.

- **v0.5.9 — the layer the one-rule-one-home rule forgot to name.** `authoring.md` has partitioned the network into Protocol, Role and Capability since v0.4, and skills are none of the three. So the two `SKILL.md` files quietly became a fourth home for protocol rules, and `agentic-protocol/SKILL.md` — the file whose entire argument is *"this skill does not contain the protocol"* — was carrying a second copy of the extension routing table. It had already drifted: the copy has five rows where `PROTOCOL.md` has six, and the missing one is `protocol-linter`. A linter reading it would match "every other lane → nothing else" and skip both `gates.md` and `authoring.md` — the two files it exists to judge against — with nothing in its output saying so. The layer table now has a **Skill** row (sequence: which lane runs when) and the test that separates the two: *would the text still be true if the run happened in a different order?* If yes it is a rule, it lives in the protocol, and the step cites it.
  - **the same gap produced a live contradiction about the ledger.** v0.4.2 changed `Open` so an absorbed row moves to `## Closed`; the superseded rule ("nothing leaves the table, it changes `state`") survived in three places — the tail of `orchestrator.md` § 1, two paragraphs below the correction that replaced it, plus Step 6.5 and the close-out checklist of `orchestrate-feature`, which also invented a `CLOSED` state no file defines. An orchestrator reading the skill and the extension got both rules and no way to tell which was current, and the one closed v0.5.x run shows exactly that: it maintained a `## Closed` table with 12 rows **and** left 13 of its 18 `Open` rows sitting there resolved.
  - **so the rule got a mechanism, because prose is what already failed.** `check_open_table` in `check_report.py`, wired into the close-out sweep next to the `gates:` check — the only command anyone runs. It judges the leading token, not the cell: `CARRIED - out of scope` passes, because a `CARRIED` row is *supposed* to carry its reason to the human, and `ABSORBED by 06` does not. 107 cases now. The closed run is left failing rather than edited to pass: that is the v0.5.6 precedent, and the failure is the evidence the drift was real.
  - **net cost, and one change reverted for not earning it.** Deduping the skills against their extension took the orchestrator's fixed context down ~2,300 chars a run. Two additions to `PROTOCOL.md` were cut after measuring them: a lane-identity rule mapping agent names to lane tokens (already derivable — the work order states `lane:`, and no run shows a lane getting it wrong) and a paragraph explaining why the file carries no version number (a human's question, answered here). `PROTOCOL.md` is loaded twelve times a run, so seven lines there cost ~10,700 chars — the trade v0.5.8b argued against, made by the same hand a day later.
  - **the stale version number went.** The file said "Version 0.4" while the plugin said 0.5.8. A second version number for an artifact that already has one is the version trap the README documents, one layer in; the plugin version is the one the orchestrator announces, and it is now the only one.
- **v0.5.8b — the context every dispatch paid for, twice.** Measured off the one closed run: 12 dispatches load **604,176 chars (~151,000 tokens) of fixed context** before any work happens — `PROTOCOL.md` in full 12 times is 33% of it, agent definitions 18%. Two rules in `authoring.md` were being broken by the files that assert them, and enforcing them is the whole change.
  - **"Agent files do not restate the shapes."** 30% of the agent definitions loaded per run — 31,549 of 106,474 chars — were paragraphs repeated verbatim in other lanes. The two worst offenders were in all eleven: a restatement of § 4's write-the-artifact-return-the-head rule, and the sentence *"nothing in this file restates them"*, which each file carried alongside a second copy of the same claim in its own "Required output format" section. Both deleted; 99 lines, no insertions.
