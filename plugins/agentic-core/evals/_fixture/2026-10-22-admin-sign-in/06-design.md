## Framework pick

Repo: next 16.4.2, drizzle-orm ^0.45.4, pg ^8.23.1, Node 22, no middleware.

| Requirement | Better Auth 1.7.12 | Auth.js (next-auth 5.0.0-beta.32) | Lucia 3.2.2 |
|---|---|---|---|
| Maintained | yes, peer `next ^16`, `drizzle-orm ^0.45.2` (npm view) | v5 still beta; v4 is latest | **deprecated on npm** (`npm view lucia deprecated`) |
| AC 12 no cookie before success | no CSRF cookie; CSRF by origin check (C1, C2) | **fails**: double-submit `authjs.csrf-token` cookie set on sign-in page/CSRF fetch | n/a |
| Server-stored sessions | DB sessions by default (`session` table) | **fails** with Credentials: docs say Credentials requires JWT sessions | — |
| No sign-up route | `emailAndPassword.disableSignUp`, and we mount no HTTP handler at all | no sign-up by default | — |
| Email+password | built-in, scrypt hash | Credentials provider, hashing ours | — |
| Revoke all of a user's sessions (D-12) | sessions are rows keyed by user_id; delete them | impossible with JWT | — |
| 8 h absolute (D-9) | `session.expiresIn` + `disableSessionRefresh` (C6) | JWT maxAge only | — |
| TOTP path (S2.2) | official `twoFactor` plugin (TOTP, backup codes) | none built in | — |
| Guardrail 5 | IP tracking can be disabled; logger can be disabled; telemetry disable-able (C9–C11) | — | — |

**Proposal: Better Auth.** The one reason it wins: it is the only maintained option that keeps sessions on the server with a credentials login and sets no pre-sign-in cookie. Auth.js fails AC 12 and server sessions outright, so no workaround is proposed (D-13).

Packages: `better-auth@1.7.12` (dependency, pinned exact). Its transitive deps (zod, kysely, jose, @noble/hashes, @better-auth/*-adapter, @better-auth/telemetry) arrive with it; the decision record names the package and states the transitive set is accepted. No other new package. `@better-auth/cli` is **not** added; the schema is hand-written from § Data model.

How it is used (binding): a single `getAuth()` in `src/server/auth/auth.ts` builds the instance lazily (env read at call time, TD-5), with:
- `database: drizzleAdapter(getDb(), { provider: 'pg', schema })`, model names mapped to the `admin_*` tables
- `secret: AUTH_SECRET`, `baseURL: SITE_URL`, `trustedOrigins: [SITE_URL]`
- `emailAndPassword: { enabled: true, disableSignUp: true, minPasswordLength: 6, autoSignIn: false }`
- `session: { expiresIn: 8*3600, disableSessionRefresh: true, cookieCache: { enabled: false } }`
- `advanced: { cookiePrefix: 'admin', defaultCookieAttributes: { sameSite: 'strict' }, useSecureCookies: SITE_URL startsWith https, ipAddress: { disableIpTracking: true } }`
- `databaseHooks.session.create.before`: set `userAgent` and `ipAddress` to null
- `rateLimit: { enabled: false }` (lockout is S2.2; no IP-keyed store), `telemetry: { enabled: false }`, `logger: { disabled: true }`
- `plugins: [nextCookies()]` (last)

## Claims to verify

For the D-7 independent checker. Each must hold on 1.7.12; check against docs and, better, a scratch run. Docs root: https://www.better-auth.com/docs

- C1 — Calling `auth.api.signInEmail` with a wrong password or unknown email sets no cookie and returns the same error code for both (`INVALID_EMAIL_OR_PASSWORD`). Docs: /docs/authentication/email-password
- C2 — Better Auth sets no CSRF cookie; CSRF protection is an Origin/`trustedOrigins` check. Docs: /docs/reference/security
- C3 — Successful sign-in sets exactly one cookie, `<prefix>.session_token` (no `session_data` while cookieCache is off, no `dont_remember` when `rememberMe` is omitted). Docs: /docs/concepts/cookies
- C4 — The session cookie is HttpOnly, SameSite=Strict via `defaultCookieAttributes`, Secure under `useSecureCookies`, value `token.signature` (HMAC with secret). Docs: /docs/concepts/cookies
- C5 — `auth.api.getSession({ headers })` in a Server Component emits no Set-Cookie for a missing, forged or expired cookie, and returns null.
- C6 — `session.expiresIn: 28800` with `disableSessionRefresh: true` gives an absolute 8 h limit; `expiresAt` is never extended. Docs: /docs/concepts/session-management
- C7 — `auth.api.signOut({ headers })` deletes the session row and, via `nextCookies()`, clears the cookie in a server action. Docs: /docs/integrations/next
- C8 — `hashPassword` / `verifyPassword` exported from `better-auth/crypto` are the same scrypt (salted) used by `signInEmail`, so a CLI-written hash signs in.
- C9 — `advanced.ipAddress.disableIpTracking: true` stops storing IPs on sessions. Docs: /docs/reference/options
- C10 — `logger: { disabled: true }` silences all framework logs (no email in output on failure).
- C11 — `telemetry: { enabled: false }` disables telemetry; check whether it is off by default in 1.7. Docs: /docs/reference/telemetry
- C12 — With `disableSignUp: true` and no HTTP handler mounted, no sign-up/reset endpoint is reachable (we mount none; checker confirms no auto-registered route exists in Next).
- C13 — Next.js 16 server actions reject a POST whose Origin does not match Host (built-in action CSRF check). Docs: https://nextjs.org/docs/app/guides/data-security (Server Actions, CSRF)
- C14 — `signInEmail` does not lowercase-sensitive-fail: we lowercase before calling, so only confirm stored email lookup is exact-match on the lowercase value; and a 6-character password passes sign-in validation with `minPasswordLength: 6`.

Escalation rule: C1, C2, C3 or C5 failing breaks AC 12 → escalate to the human (D-13). Others failing → design revision, not escalation.

## Data model

New file `src/db/schema/auth.ts`, re-exported from `src/db/schema/index.ts`; migration `npm run db:generate -- --name admin_auth` → `0003_admin_auth`. Columns follow Better Auth's core schema (required by the adapter), table names prefixed:

- `admin_users`: `id text pk`, `name text not null` (always the constant `'admin'`; no personal data), `email text not null unique` (stored lowercased, trimmed), `email_verified boolean not null default false`, `image text null`, `created_at`, `updated_at` timestamptz not null default now.
- `admin_accounts`: `id text pk`, `account_id text not null` (= user id), `provider_id text not null` (= `'credential'`), `user_id text not null fk → admin_users.id on delete cascade`, `password text null` (scrypt hash), `access_token`, `refresh_token`, `id_token`, `scope text null`, `access_token_expires_at`, `refresh_token_expires_at timestamptz null`, `created_at`, `updated_at`. Unique `(provider_id, user_id)`.
- `admin_sessions`: `id text pk`, `token text not null unique`, `user_id text not null fk cascade`, `expires_at timestamptz not null`, `ip_address text null`, `user_agent text null` (both always null, hook), `created_at`, `updated_at`. Index on `user_id`.
- `admin_verifications`: `id text pk`, `identifier text not null`, `value text not null`, `expires_at`, `created_at`, `updated_at` — required by the framework, unused in S2.1.

S2.2 will add `admin_users.two_factor_enabled` and a `admin_two_factors` table via the plugin; nothing here blocks it.

## Contract

### Guard — `src/server/auth/guard.ts` (`import 'server-only'`)

```ts
export type AdminIdentity = { userId: string; email: string | null };
export type AdminCheck =
  | { kind: 'admin'; admin: AdminIdentity }
  | { kind: 'anonymous' }      // none, forged, malformed, expired, signed out, ended by re-run
  | { kind: 'unavailable' };   // store unreachable or any thrown error: fail closed (AC 21)

export function checkAdminSession(headers: Headers): Promise<AdminCheck>;   // core, testable
export function requireAdminPage(): Promise<AdminIdentity>;                 // React cache()d per request
export function requireAdminAction(): Promise<AdminIdentity | AdminRefusal>;
export type AdminRefusal = { ok: false; reason: 'unauthenticated' | 'unavailable' };
```

- `checkAdminSession` calls `getAuth().api.getSession({ headers, query: { disableCookieCache: true } })`, catches everything to `unavailable`, logs only `admin-guard: unavailable (<errorCode>)` via `src/server/error-code.ts`.
- `requireAdminPage`: `anonymous` → `redirect('/admin/acceso?aviso=sesion')`; `unavailable` → `throw new AdminUnavailableError()` rendered by `src/app/admin/error.tsx` as the Unavailable screen. Never a 500 page, nothing admin rendered.
- `requireAdminAction`: returns the refusal; the action returns it with no effect. Every admin server action's **first statement** is this call.
- Future admin route handlers use `requireAdminRequest(request)` → 401 (anonymous) / 503 (unavailable), empty body. Not built in S2.1 (no admin route handler exists) but defined here so S2.3+ do not invent one.
- Where it runs: in every admin `page.tsx` and in `admin/(shell)/layout.tsx` (layout is not the protection; the page call is). No middleware/proxy file.
- The guard is the only reader of the session cookie in src.

### Sign-in / sign-out — `src/server/auth/actions.ts` (`'use server'`)

```ts
export type SignInState =
  | { status: 'idle' }
  | { status: 'invalid'; email: string; fieldErrors: { email?: 'required' | 'invalid'; password?: 'required' } }
  | { status: 'rejected'; email: string }      // wrong password AND unknown email, identical (AC 10)
  | { status: 'unavailable'; email: string };  // store down, origin refused, anything unexpected
export function signInAction(prev: SignInState, form: FormData): Promise<SignInState>;  // success → redirect('/admin')
export function signOutAction(): Promise<void>;  // always ends at redirect('/admin/acceso?aviso=salida')
```

- `email` in state is the trimmed value as typed, never lowercased for display; the lookup uses lowercase.
- Validation order: email trim → empty `required`, no `@`-shaped match `invalid`; password empty `required`; any field error returns `invalid` without a lookup.
- Signed-in visitor on `/admin/acceso` → `redirect('/admin')`.
- Query `aviso`: `sesion` → `signInRequired` notice; `salida` → `signedOut`; anything else ignored. State 2b (`sessionEnded`) is **not built**: the guard cannot tell invalid from absent without breaking AC 19.
- `SESSION_LIFETIME_HOURS = 8` exported from `src/server/auth/config.ts`; used by `getAuth()` and passed to the `signInRequired` copy.

### Cookie

`admin.session_token` (`__Secure-admin.session_token` under HTTPS): HttpOnly, SameSite=Strict (AC 13 literally: not sent on any cross-site request), Path=/, Secure iff `SITE_URL` is https, Max-Age 28800, value opaque signed token. The only cookie the app ever sets.

### create-admin CLI — `src/cli/create-admin.ts`

- Invocation: `npm run create-admin` and `docker compose run --rm app create-admin`. **Takes no arguments**; any argument → `usage: create-admin  (reads email, then password, from stdin)` and exit 2. Reason: npm echoes script args to the console, so `--email` would print the email (AC 28).
- TTY: prompts `Email: ` (echoed) then `Password: ` (not echoed). Non-TTY (tests, `-T`): line 1 email, line 2 password; strip only the trailing `\r?\n`.
- Refusals, exit 2, nothing written, text never contains the inputs: missing/invalid email, missing password, password < 6 chars.
- Success: one transaction in `src/server/auth/accounts.ts` `upsertAdmin(db, email, password)` → creates user+credential account, or updates the hash and deletes all `admin_sessions` of that user. Prints `create-admin: created` or `create-admin: updated, sessions ended`. Exit 0. Failure: `runCli` (exit 1, code only).
- `accounts.ts` imports `hashPassword` from `better-auth/crypto` and Drizzle only — **not** `getAuth()` (no next/headers in the CLI graph).
- Entry point: add `create-admin` to the `migrate|seed|import-feeds` arm and the usage line. npm script: `npm run cli:build && node --env-file=.env --conditions=react-server dist/cli/create-admin.js`.

## Decisions

- Better Auth is used only through `auth.api.*`; no HTTP handler is mounted. Nobody adds `toNextJsHandler`.
- All emails are trimmed and lowercased before every lookup and write, in our code (`normalizeEmail` in `accounts.ts`), not left to the framework.
- Guard result names are `admin | anonymous | unavailable`; action refusals `unauthenticated | unavailable`.
- Sign-in path `/admin/acceso`; shell `/admin`; notices via `?aviso=sesion|salida`.
- No `sessionEnded` variant (UX state 2b dropped).
- Unmatched `/admin/*` URLs get the public 404, not an admin one.
- Admin user `name` is the constant `'admin'`.
- CLI exit codes: 0 ok, 2 usage/refusal, 1 failure; CLI output English like the other verbs.
- `rateLimit` off in S2.1; lockout is S2.2's.
- `SESSION_LIFETIME_HOURS` is the single source for the 8 h.
- Session cookie is SameSite=Strict, not the framework default Lax.

## Risks

- Raw session token in DB: S2.2 or a later hardening could hash it; for a local-only build the exposure needs DB access, which already gives everything.
- CLI CJS → ESM: if `require('better-auth/crypto')` fails under Node 22's require(esm), backend reports BLOCKED rather than switching module systems; the fix (an ESM CLI build) is a decision.
- `trustedOrigins` is `SITE_URL`; opening the app as `localhost` instead of `127.0.0.1` makes sign-in return `unavailable`. Docs must say so.
- Next may override a `headers()` `Cache-Control` on dynamic pages; it already emits `no-store` for force-dynamic, so the test asserts `no-store` is present, not the exact string.
- SameSite=Strict means following a link to /admin from another site arrives anonymous and lands on sign-in; acceptable for three admins, and it is what AC 13 says.
