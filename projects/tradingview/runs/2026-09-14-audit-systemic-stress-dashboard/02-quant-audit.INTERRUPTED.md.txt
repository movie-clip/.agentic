## Method and anchor

`protocol/gates.md` § 2 forbids a gate that reads only the source the work was
built from. There is no published indicator this script reproduces — its header
says so outright — so anchor 1 in the capability pack (the cited primary source)
does not exist here. I used anchors 2 and 4:

- **Anchor 2, hand-computed worked examples.** I reimplemented percentile rank,
  rate of change and the weighted average from their standard definitions in a
  throwaway script, ran the script's own inputs through it, and compared. The
  reimplementation was written from the definitions, not from the Pine.
- **Anchor 4, dimensional and boundary analysis.** Constant series, missing
  component, component appearing mid-chart, negative weight, each threshold
  boundary from both sides, and both warm-up lengths.
- Plus Pine's documented semantics for `ta.percentrank`, `ta.roc` and
  `request.security` as the external reference for the building blocks — which is
  where FINDING 1 comes from, and it is not visible from the script's own text.

I did not run the script. No Pine runtime exists outside TradingView's editor,
so nothing here is a claim about what the chart shows; it is a re-derivation of
what the stated formulas must produce.

## FINDING 1

```
severity:   MATERIAL  (blocking)
where:      systemic_stress_dashboard.pine:63, :64, :69, :70
claim:      vixPct = na(vixClose) ? na : ta.percentrank(vixClose, percentileLookback)
            and the same shape on corPct, creditRawStress (ta.roc) and creditPct.
            The tooltip at line 39 says the percentile is measured against
            `percentileLookback` bars of history; the input at line 40 is titled
            "Credit Ratio Rate-of-Change Length" in bars.
actual:     ta.percentrank and ta.roc carry internal series state. Pine evaluates
            a ternary's branches lazily, so on any bar where the guard is true the
            call is never reached and its buffer does not advance. The window then
            counts CALLS, not chart bars.
```

Worked example — HYG/LQD unavailable for three interior bars, `creditRocLen = 20`,
a ratio rising a uniform 0.1% per bar:

| bar | roc over 20 chart bars | roc as the code computes it (20 calls) |
|---|---|---|
| 29 | 1.9822 | 1.9822 |
| 33 | 1.9743 | **2.2772** |
| 40 | 1.9608 | **2.2616** |
| 50 | **na** | **2.2395** |

Two separate wrongnesses. At bars 33 and 40 the rate of change is overstated by
about 15% because the window silently spans 23 chart bars instead of 20. At bar
50 the honest answer is `na` — the 20-bars-ago value does not exist — and the
code produces a plausible 2.24 instead, which is exactly the failure guardrail 5
names.

**impact:** the trader reads "credit stress over the last 20 bars" and is shown a
number measured over a longer, variable and unstated window, with no visual cue
that the window moved. The same applies to all three percentile ranks, where the
distortion compounds: a 252-call window can span far more than one trading year.

**expected:** hoist the stateful call out of the ternary and guard only its
result, e.g. `vpRaw = ta.percentrank(vixClose, percentileLookback)` on every bar,
then `vixPct = na(vixClose) ? na : vpRaw`. TradingView's own compiler warns on
this pattern ("should be called on each calculation for consistency"), so the
editor will flag all four lines when the script is next loaded.

**Not a disclosed caveat.** The header discloses untuned weights and a symbol
that may not resolve. It does not disclose that the lookback lengths are
approximate.

## FINDING 2

```
severity:   MATERIAL  (blocking)
where:      systemic_stress_dashboard.pine:83 (with :73-:80)
claim:      header line 16 — "Stress Impulse : how much Systemic Stress has moved
            over the last N bars (negative = stress easing, positive = stress
            building)".
actual:     systemicStress is a weighted average over whatever subset of
            components is non-na on that bar. When the subset changes, the
            difference systemicStress - systemicStress[impulseLen] subtracts two
            differently-defined indices, and the result is attributed to a move in
            stress.
```

Worked example — VIX percentile 40 and credit percentile 30 on both bars, nothing
moving. COR1M has no data before its first bar and is 80 on it. Defaults
`wVix=1, wCor=1, wCredit=0.5`:

```
bar t-1, COR1M na :  (40*1 + 30*0.5) / 1.5   = 36.6667
bar t,   COR1M 80 :  (40*1 + 80*1 + 30*0.5) / 2.5 = 54.0000
stressImpulse      =  54.0000 - 36.6667      = +17.3333
```

The pane plots a +17.3 orange spike labelled "stress building" on a bar where
every underlying component was flat.

**impact:** this is guaranteed, not hypothetical, on any chart whose history
predates a component's data start — COR1M and HYG both start far later than VIX.
The plotted "Systemic Stress" line on such a chart is two or three different
indices spliced end to end with no marker, and the impulse series carries a false
spike at each splice. `bgcolor` and the regime label can also flip at the splice.

**expected:** either hold `systemicStress` at `na` unless the same component set
is available at `t` and at `t-impulseLen`, or hold `stressImpulse` at `na` across
any bar where the effective weight set changed. Both degrade visibly, which is
what guardrail 5 asks for; the current code substitutes a plausible value.

**Note the boundary with what is disclosed.** The header's renormalisation
promise is about a symbol that never resolves, and for that case the arithmetic
is correct (§ What reproduced correctly, case B). Nothing in the header covers a
component that resolves for part of the chart and not the rest.

## FINDING 3

```
severity:   MATERIAL  (not blocking)
where:      systemic_stress_dashboard.pine:57-60 with :63, :64, :70
claim:      header lines 21-24 — if COR1M "fails to resolve ... check the COR1M
            Percentile cell; if it stays blank, the symbol didn't resolve".
actual:     that promise covers non-resolution only. request.security defaults to
            barmerge.gaps_off, which forward-fills the last available value across
            bars the foreign symbol did not trade. A forward-filled constant run
            is not na, so the cell does not stay blank.
```

Boundary case, computed: `ta.percentrank` over a constant window returns **100.0**
under the `<=` tie rule Pine documents (and 0.0 under a strict `<`). Either way a
frozen or stale feed produces an extreme percentile, and 100 is "Stressed" — the
red background, the worst regime label — produced by a feed that stopped
updating.

**impact:** the failure mode the header trains the reader to look for is a blank
cell. The failure mode that actually occurs on a holiday, a half-day, or a chart
whose session differs from the component's, is a maximum-stress reading. The
trader has been told the wrong tell.

**expected:** either pass `barmerge.gaps_on` so an absent bar reads `na` and the
cell genuinely blanks, or detect a stalled component (unchanged for n bars) and
render it `n/a`. State in the header which was chosen.

## What reproduced correctly

Reproduced from the definitions, not read off the code. These are the places a
fix must not disturb.

**The credit sign is right.** `ta.roc(x, n) = 100 * (x - x[n]) / x[n]`, so a
HYG/LQD ratio falling 1.00 → 0.95 over 20 bars gives roc = −5.0 and
`-ta.roc(...)` = **+5.0**: junk underperforming reads as rising stress, as header
lines 66-67 claim. Rising 1.00 → 1.05 gives **−5.0**. The negation composes with
`ta.roc` in the stated direction. The pack's sign convention (positive is risk-on)
is inverted here, and the header, the plot titles and the table labels all say
"Stress" — the inversion is labelled, which is what the convention requires.

**The renormalisation arithmetic is right.** With all three present
(vp=40, cp=80, kp=30, weights 1/1/0.5) it returns **54.0**, matching
(40 + 80 + 15) / 2.5 by hand. With COR1M absent it returns **36.6667**, matching
(40 + 15) / 1.5 — the composite stays a genuine weighted average on the surviving
components, on the same 0-100 scale, with no scale distortion. The header's
"excludes it and re-normalizes" claim is accurate for the whole-series case.
FINDING 2 is about the transition between these two states, not about either
state.

**The regime bands have no gap and no overlap**, at the defaults:

| value | label | bgcolor red? |
|---|---|---|
| 24.999 | Calm | no |
| 25 | Normal | no |
| 49.999 | Normal | no |
| 50 | Elevated | no |
| 74.999 | Elevated | no |
| 75 | Stressed | **yes** |

Every band is half-open `[lower, upper)`, the chain of `<` comparisons is
exhaustive, and `bgcolor`'s `>= elevatedMax` (line 110) fires on exactly the set
the label calls "Stressed" — the two agree at the boundary, which is the easiest
place for a dashboard to contradict itself and this one does not.

**The stressImpulse na guard is correct** for the warm-up case it was written for.
`systemicStress[impulseLen]` on a chart with fewer than `impulseLen` prior bars
returns `na`, line 83 catches it, and `fmt` (line 117) renders the literal
`"n/a"`. Indexing a series by an input int is legal and reaches no future bar.

**Warm-up bar counts**, for whoever tunes the defaults: `vixPct` and `corPct`
first become non-`na` after 252 bars; `creditPct` after 272 (20 for the roc, then
252 for the percentile). That 20-bar window in which the composite is VIX+COR1M
only, before credit joins, is FINDING 2 firing on a fresh chart with all three
symbols resolving.

## Repaint analysis

Required in every artifact that touched a computed series, even where the answer
is that it does not.

| pattern from the pack's table | present? |
|---|---|
| higher-timeframe value used before that timeframe closes | **no** — all four calls request `timeframe.period`, the chart's own timeframe |
| `ta.pivothigh`/`ta.pivotlow` plotted at the pivot bar | **no** — no pivot functions in the script |
| threshold computed from a window including the current unclosed bar | **partly** — see below |
| `ta.valuewhen` on a repainting condition | **no** — not used |
| alert not guarded by `barstate.isconfirmed` | **not applicable** — the script emits no `alert()` or `alertcondition()` |
| `strategy.entry` on an intrabar condition | **not applicable** — `indicator()`, not `strategy()` |

The one live case: `ta.percentrank` includes the current bar's value as the value
being ranked, and on the last bar that value is the developing close. So the last
bar's Systemic Stress, its regime label, its background shading and the table
readings all move intrabar and settle at the close. **Historical bars do not
repaint** — once a bar closes its percentile is fixed, nothing is indexed
forward, and `lookahead` is off by default.

This is the normal and arguably desirable behaviour for a live dashboard, and it
is why I grade it below a finding. What is missing is the sentence saying so: the
header does not tell the reader that the last bar's reading is provisional and
that a regime label can flip between "Elevated" and "Stressed" before the close.
Per the pack, a repaint that is disclosed and harmless is MINOR; this one is
harmless and **undisclosed**, so it belongs in the header alongside FINDING 6's
symbol statement rather than being left for the reader to discover.
