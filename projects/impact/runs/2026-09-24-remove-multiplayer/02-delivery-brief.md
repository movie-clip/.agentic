## Open decisions
- Client and Server load flags: remove outright, or keep as content filters?
  Today they are the only per-asset filter (LevelCrate uses Client|SetActiveScene, CharacterSkinCrate uses Client only). In a single Local world both always load, so they filter nothing. Removing them simplifies authoring; keeping them costs nothing but leaves a concept that means nothing. Recon could not tell if you use Server-only or Client-only prefabs deliberately.
- Serialized crate and prefab values: if flags are removed, migrate existing assets, or accept resave via a compatible enum (keep bit values), or hand-fix?
  Only gameWorldStateRunner.prefab (loadFlags 3, worldType 0) was checked. Every crate asset with a serialized BaseGameCrate Flags value is unchecked.
- Remove com.unity.multiplayer.center and ProjectSettings/MultiplayerManager.asset?
  It is editor onboarding tooling, roles disabled, no dependents in local packages. Removing is recommended by scope but it is your call; Unity may re-create the settings asset if the package returns.
- Rename "Authoritative" naming (GameAuthoritativeConfiguration, ConfigureLocalAuthoritativeWorld, AuthoritativeCharacterSkinLoadSystem)? Recon says it is naming only, not netcode. Default: leave it, since renaming is churn without value.
